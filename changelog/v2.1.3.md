# Tether v2.1.3 — Delivery confirmation (stop guessing whether an inject landed)

Replaces blind retry with **delivery confirmation**, fixing the "same message injected
over and over" behavior when an agent can't acknowledge.

## The problem

v2.1.1's retry loop used the read-receipt (ACK) as its only success signal: inject the
handle-line, and if the agent hadn't run `tether_receive` yet, re-inject — up to 8 times.
That conflates two different things:

- **Delivery** — the line reached the agent's prompt box (what can lose a redraw race)
- **Acknowledgment** — the agent ran `tether_receive` and acted (needs the agent to be
  *able* to act: MCP up, not rate-limited, not mid-task)

When an agent was alive but couldn't act (e.g. rate-limited, or its MCP transport was
down), the line *was* delivered but never ACK'd, so the loop kept re-injecting the same
message into its box — futile spam.

## The fix

Konsole's D-Bus interface exposes `getAllDisplayedText()` — the visible viewport as text.
So delivery is now confirmed directly: after injecting, read the screen back and look for
the handle. If it's there, the message landed — stop, regardless of whether the agent can
ACK. It will act on the line (which sits in its box) whenever it recovers.

- `konsole_driver.get_displayed_text()` / `screen_contains()` — viewport read-back.
- `konsole_deliver` confirms on inject: if the handle is on screen, the delivery is
  resolved immediately and no retry is ever scheduled (the common case).
- The retry loop now terminates on **delivered** (handle on screen) or **acked** (read
  receipt) or **unbound** (tab closed) — and only re-injects when the handle is genuinely
  not on screen (a real lost race), re-confirming each time.
- `max_attempts` is now a safety backstop (default 3) for a pathological never-landing
  inject, not the primary stop. A delivered-but-unacked message no longer spams.

## Net

A message is injected, confirmed on screen, and the loop stops — even if the recipient is
down, rate-limited, or busy. No more repeated injections of the same tmail.
