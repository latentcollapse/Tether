# v1.5: Shared Task Board

This release adds a first-class persistent task board to Tether — a shared work-item
layer that any agent (Claude, Gemini, Kilo) or human can read and write through the MCP.

Tasks were previously tracked in Matt's head or in tmails. Neither survives context
compaction or cross-session coordination. The task board fixes this.

### 📋 Task Board

Five new tools backed by a dedicated SQLite schema (separate from the content-addressed
handle store — tasks need stable mutable IDs, not BLAKE3 hashes):

- **`tether_task_create`** — Create a task with a human-readable ID (`hlx-gap1`, `prism-i64`),
  title, description, priority (p0–p3), assignee, and tags.
- **`tether_task_update`** — Update status (`open`, `in_progress`, `blocked`, `done`),
  priority, assignee, description, or title. Any agent can update any task.
- **`tether_task_list`** — List all tasks, optionally filtered by status, assignee, or priority.
- **`tether_task_get`** — Get a single task by ID with full comment history.
- **`tether_task_comment`** — Append a progress note or observation from any agent.
  Visible to all participants. Bumps `updated_at` on the task.

### 🗄️ Schema

Two new SQLite tables alongside existing `tether_handles`:

```sql
tether_tasks         -- id, title, description, status, priority, assignee, created_by, timestamps, tags
tether_task_comments -- task_id, author, text, created_at
```

Added via `_init_tasks_db()` called from `_init_db()` — existing databases migrate
automatically on first startup.

### Design note

Tasks intentionally do not use the content-addressed handle model. A task's identity
must survive status updates; a new BLAKE3 hash on every edit would break cross-agent
coordination. Task IDs are stable slugs chosen by the creator.
