# Tether v1.8.3 — Delivery Reliability

Patch release fixing ping delivery priority inversion, idle detection gaps, and
direct-write ping bypass. All three bugs could cause messages to land silently
after tmux session renames or direct DB writes outside the MCP path.

## Fixes

### `_fire_ping` priority inversion (mcp_server.py)
- **Before:** tmux inject was primary; HTTP daemon was fallback. After `tmux rename-session`, tmux inject succeeds immediately (session exists) but has no idle detection — fires into active prompts, corrupts input.
- **After:** HTTP daemon is primary (idle-aware); tmux inject is fallback only when daemon is unreachable. Delivery is now idle-safe by default.

### `_send_message_with_ping` helper (__main__.py)
- Added `_send_message_with_ping()` — wraps `collapse("messages", ...)` with an automatic HTTP ping to the recipient's registered daemon.
- Fixes the long-standing gap where direct DB writes (outside MCP) dropped pings silently.
- Falls back to `~/.tether_notify` file when HTTP is blocked (sandboxed processes).

### Idle pattern + pane resolution improvements (ping_daemon.py)
- Added idle patterns for Claude Code session toolbar (`bypass permissions`, `auto-compact`, `esc to interrupt`) and Codex CLI (`Type your message`).
- Added `deepseek`/`hermes` agent pattern recognition.
- `resolve_pane()` now checks `/tmp/tether-pane-{agent}` pin file first before scanning all panes — survives session renames without breaking pane targeting.
- Notification format now includes subject: `[Tether] {sender}: {subject}  Handle: '{handle}'`

## Notes

- Ping delivery remains best-effort and never blocks message storage.
- The `_fire_ping` fix resolves intermittent missed pings that occurred after `tether_session_init.sh` renamed tmux sessions.
