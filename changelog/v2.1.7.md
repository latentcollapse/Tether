# Tether v2.1.7 — legacy queue retirement

This follow-up hardens the v2.1.6 Konsole delivery fix against unsafe prompt
text persisted by older Tether versions.

## Security

- Rewrites every stored Konsole queue line from validated handle and recipient
  metadata into the inert, sender-independent v2.1.6 notice format.
- Retires malformed legacy rows that cannot produce a validated inert notice.
- Keeps the durable message payload intact; only obsolete prompt-delivery text
  is replaced.

## State consistency

- Reports held, unsubmitted notices as `notified`, matching their pending queue
  state.
- Reconciles older `delivered` records that still have pending, unsubmitted
  queue work.
- Normalizes terminal queue rows to an exhausted retry budget with no schedule.

## Verification

- 61 focused delivery, migration, process-identity, retry, and SQLite tests pass.
- Production migration leaves zero non-inert queue lines and zero terminal rows
  with a live schedule or partial retry budget.
