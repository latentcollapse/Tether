# Tether v2.1.6 — Konsole delivery security

This stability release closes an unsafe prompt-delivery path discovered after an
agent process exited and its Konsole tab returned to a shell.

## Security

- Re-verifies the live foreground process immediately before every prompt write
  and submission. Persisted bindings and stamped tab titles are no longer accepted
  as process identity.
- Pins queued delivery to the original foreground PID. If that process exits or
  restarts, automatic injection stops and the durable inbox remains the recovery
  path.
- Removes sender-controlled subject, body, and sender data from injected text.
  Wake text is now a fixed, validated shell comment containing only the message
  handle and recipient.
- Applies the same checks to direct delivery, retry delivery, and detached
  follow-up submission.

## Stability

- Terminal pending rows now clear `next_attempt_at` and exhaust their retry budget.
- Existing SQLite databases migrate `next_attempt_at` to nullable storage under a
  serialized writer lock.
- Legacy retry rows without an original PID are retired from automatic injection;
  their messages remain durable and unread.
- A replacement process never inherits an earlier process's delivery attempts.

## Verification

- 59 focused delivery, process-identity, retry, migration, and SQLite tests pass.
- 40 additional crypto, handle, MCP, ping, TOON, and PAKE tests pass.
- Live process classification accepts the active Codex, Claude, and Cursor agents
  and rejects the Fish shell in a neighboring Konsole tab.
