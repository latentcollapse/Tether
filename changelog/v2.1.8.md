# Tether v2.1.8 — single-owner delivery stability

This patch replaces the layered Konsole retry machinery with one deliberately
small delivery primitive.

## Delivery

- `send` persists one `(recipient, handle)` row and never writes a prompt.
- One singleton dispatcher resolves the recipient's live process on every tick.
- Each tick attempts at most one pending handle per recipient.
- Busy, drafted, unknown, or wrong-target composers receive zero bytes.
- Positively idle prompts receive one atomic, inert `# [Tether] resolve ...` line.
- Queue rows have only `pending` and `delivered` states; retry budgets, cached
  bindings, per-message waiters, and drain semantics are removed.

## Operations

- Adds a backend kill switch: `tether delivery pause|resume|status`.
- The dashboard and agent receivers are no longer delivery dependencies.
- The retired per-message follow-up entry point is a harmless tombstone for
  stale services left by older installations.

## Verification

- 76 tests pass against the exact staged patch.
- Falsifiers cover zero-write busy prompts, atomic idle submission, oldest-only
  dispatch, live identity lookup, legacy migration, pause behavior, and MCP
  resolve convergence.
