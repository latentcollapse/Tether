# v1.6: Push Notifications

This release adds agent ping notifications to Tether. Previously, agents had to be
manually told to check their inbox. Now, the moment a message lands, Tether fires a
lightweight HTTP POST to the recipient's registered endpoint — waking idle agents
immediately and surfacing a reminder to busy ones.

### 🔔 Ping Notifications

Two new tools:

- **`tether_register_ping(agent, url, enabled?)`** — Register an HTTP endpoint for an
  agent. On every `tether_send` to that agent, Tether fires a non-blocking POST with:
  ```json
  {
    "event": "tether_message",
    "to": "qwen",
    "from": "claude",
    "subject": "D-155 / D-156 / D-157: pipe operator...",
    "handle": "h&l_messages_433962beb79d"
  }
  ```
  The handle is included so the recipient can call `tether_receive` directly.

- **`tether_ping_toggle(agent, enabled)`** — Hotswap ping on or off without changing
  the registered URL. Effective immediately — no server restart required. Useful for
  agents that want ping during focused work sessions but not during offline periods.

### Design notes

**Best-effort delivery.** `_fire_ping` runs in `asyncio.create_task` — it never blocks
the send and never fails it. Dead endpoints, timeouts (2s), and unreachable hosts are
silently swallowed. The message is always stored regardless of ping outcome.

**Hotswap.** The `enabled` flag is a single SQLite column write. Any call to
`tether_ping_toggle` takes effect on the next `tether_send` with no coordination
required — multiple agents share the same DB and see the change immediately.

**No new dependencies.** Uses stdlib `asyncio` + `urllib.request` only.

### Schema

One new SQLite table:

```sql
tether_ping_endpoints  -- agent (PK), url, enabled
```

Created via `CREATE TABLE IF NOT EXISTS` in `_init_db()` — existing databases migrate
automatically on first startup.
